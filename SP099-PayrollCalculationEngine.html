1

Resumen Ejecutivo

SP099 agrega un motor de cálculo embebido directamente en la entidad HR_Attribute, permitiendo definir fórmulas de nómina sin necesidad de crear registros AD_Rule separados. El motor soporta dos modos:

🧮 Tipo E — Expresión

Fórmulas matemáticas y condicionales evaluadas en Java puro mediante un parser recursivo descendente. No requiere motor de scripting externo.

Ejemplo: IF(_Days > 15, ROUND(_Days * 100, 2), 0)

📜 Tipo S — Script

Scripts completos ejecutados vía JSR-223 (JavaScript, Groovy, Python) o BeanShell. Soporta lógica arbitraria con acceso completo al contexto de nómina.

Ejemplo: var r = _Days * 200; r; (JavaScript)

Compatibilidad total: Los conceptos existentes con AD_Rule_ID y sin CalculationTypeValue siguen funcionando exactamente igual. El cambio es estrictamente aditivo.
2

Contexto y Problema

Flujo previo

Cuando un concepto de nómina tiene HR_Concept.Type = 'E' (TYPE_RuleEngine), el proceso MHRProcess.createMovementFromConcept() delega el cálculo a executeScript(concept, attribute.getAD_Rule_ID(), ...).

Problema

  • Cada fórmula, por simple que sea, requiere crear y mantener un registro AD_Rule separado.
  • Para fórmulas como _Days * 100 es necesario ir al módulo de Reglas, crear la regla, asociarla, guardar y regresar.
  • El mantenimiento masivo de reglas simples es engorroso y difícil de auditar.
  • No hay validación de sintaxis en tiempo de edición.

Solución

Agregar campos de cálculo directamente a HR_Attribute e implementar un motor que los evalúe. El patrón es equivalente al de AD_PrintFormatCalculation, que ya demostró ser ergonómico en el módulo de reportes.

6.1 Gramática del lenguaje

expression    ::= or_expr
or_expr       ::= and_expr  ( 'OR'  and_expr  )*
and_expr      ::= comparison ( 'AND' comparison )*
comparison    ::= additive  ( ('='|'!='|'<'|'<='|'>'|'>=') additive )?
additive      ::= multiplicative ( ('+'|'-') multiplicative )*
multiplicative::= unary ( ('*'|'/'|'%') unary )*
unary         ::= ('-'|'NOT')? primary
primary       ::= NUMBER | STRING | '(' expression ')' | IDENTIFIER ['(' args ')']
args          ::= expression (',' expression)*

PayrollCalculationEngine — Motor Orquestador

Archivo: hr_and_payroll/src/main/java/org/spin/hr/util/PayrollCalculationEngine.java

API pública

public class PayrollCalculationEngine {

    /** Punto de entrada principal. Delega según CalculationTypeValue. */
    public static Object calculate(MHRAttribute attribute,
                                    Map<String, Object> scriptCtx);
}

7.1 Tipo E — Expresión

Delega directamente a PayrollExpressionEvaluator.evaluate(expression, scriptCtx). No crea hilos adicionales ni motores JSR-223. Es la opción más eficiente y segura.

7.2 Tipo S — Script

BeanShell (B)

Usa el Scriptlet integrado, exactamente igual al motor actual de nómina. El script recibe los imports estándar prepended automáticamente y debe declarar la variable result.

JSR-223: JavaScript (J), Groovy (G), Python (P)

  • Usa ScriptEngineManager estático con caché ThreadLocal por nombre de motor.
  • Cada variable del scriptCtx se inyecta en el SimpleScriptContext con scope ENGINE_SCOPE.
  • La variable result se pre-inicializa a 0.0 (o null para tipos Date/Text).
  • La ejecución corre en un hilo separado y se interrumpe si supera el ScriptTimeout.

7.3 Timeout y seguridad

Patrón bloqueadoMotivo
Runtime.getRuntimePreviene ejecución de comandos del SO
System.exitPreviene cierre abrupto de la JVM
Class.forNamePreviene carga dinámica de clases peligrosas
ProcessBuilderPreviene creación de procesos externos
java.io.FilePreviene acceso al sistema de archivos
java.net.Previene acceso a red

Timeout por defecto: 5000 ms. Si el script supera este límite, el hilo se interrumpe y se lanza AdempiereException("Script execution timed out after N ms"). Configurable por atributo mediante el campo ScriptTimeout.

Integración en MHRProcess

Archivo: hr_and_payroll/src/main/java/org/eevolution/hr/model/MHRProcess.java
Método: createMovementFromConcept() — alrededor de la línea 1244

Cambio aplicado

if (MHRConcept.TYPE_RuleEngine.equals(concept.getType())) {
    logger.info("Processing -> Rule to Concept " + concept.getValue());
    if (activeConceptRule.contains(concept)) {
        throw new AdempiereException("Recursion loop detected in concept "
                                    + concept.getValue());
    }
    activeConceptRule.add(concept);

    Object result;
    if (!Util.isEmpty(attribute.getCalculationTypeValue())) {
        // ► Nuevo motor embebido (SP099)
        result = PayrollCalculationEngine.calculate(attribute, scriptCtx);
    } else {
        // ► Motor clásico AD_Rule (backward compatible)
        result = executeScript(concept, attribute.getAD_Rule_ID(),
                               attribute.getColumnType());
    }

    activeConceptRule.remove(concept);
    movement.setColumnValue(result);
    if (description != null)
        movement.setDescription(description.toString());
}

Resultado: Calcula proporción mensual usando el primer valor disponible entre SALARIO_BASE y SALARIO_MIN.

-- Calcula días efectivos del período y paga 50 por día
CalculationTypeValue = 'E'

Resultado: Si el período va del 01/03 al 31/03 → 30 días → 1500

-- Horas extra: si días > 22 paga las horas extra con recargo del 150%
CalculationTypeValue = 'E'

                           ROUND((_Days - 22) * 8 * SALARIO_HORA * 1.5, 2),
                           0)'
Resultado: Si _Days = 25 y SALARIO_HORA = 50: ROUND((25-22) * 8 * 50 * 1.5, 2) = 1800.00
Script — JavaScript Cálculo con lógica de negocio compleja 
-- Configuración en HR_Attribute:
CalculationTypeValue = 'S'
ScriptEngine         = 'J'
ScriptTimeout        = 3000

-- ScriptCode:
var baseSalary  = process.getAttribute('SALARIO_BASE');
var days        = _Days;
var dailyRate   = baseSalary / 30;
var bonus       = days >= 28 ? dailyRate * 2 : 0;

result = Math.round((dailyRate * days + bonus) * 100) / 100;
Resultado: Pago proporcional + bono de 2 días si trabajó 28 o más días.
Script — Groovy Deducción escalonada por tramos 
-- ScriptCode (Groovy):
def salary = process.getAttribute('SALARIO_NETO')

def deduction
if (salary <= 5000) {
    deduction = salary * 0.05
} else if (salary <= 15000) {
    deduction = salary * 0.10
} else {
    deduction = salary * 0.15
}

result = deduction.round(2)
Resultado: Deducción del 5%, 10% o 15% según tramo salarial, redondeada a 2 decimales.
Script — BeanShell Cálculo de antigüedad 
-- ScriptCode (BeanShell - equivalente al motor clásico de nómina):
MHREmployee emp      = _HR_Employee;
Timestamp   hireDate = emp.getStartDate();
Timestamp   today    = new Timestamp(System.currentTimeMillis());

long diffMs   = today.getTime() - hireDate.getTime();
long years    = diffMs / (1000L * 60 * 60 * 24 * 365);

// Bono de antigüedad: 500 por año completo de servicio
double result = years * 500;
Resultado: Si el empleado tiene 5 años de antigüedad → 2500.00

Seguridad

Tipo E — Expresión (sin riesgos de ejecución arbitraria)

El evaluador de expresiones es un parser en Java puro. No invoca ningún motor de scripting externo. Solo puede acceder a las funciones y variables explícitamente soportadas. No existe forma de ejecutar código Java arbitrario desde una expresión.

Tipo S — Script (validación previa)

Antes de ejecutar cualquier script, PayrollCalculationEngine valida que el código no contenga ninguno de los patrones prohibidos. Si alguno se detecta, se lanza AdempiereException y el proceso se detiene.

Patrones bloqueados: Runtime.getRuntime, System.exit, Class.forName, ProcessBuilder, java.io.File, java.net., java.lang.reflect, Thread.sleep, System.load, ClassLoader

Timeout de ejecución

Los scripts JSR-223 corren en un hilo separado con un join de máximo ScriptTimeout ms. Si el hilo sigue vivo al vencer el timeout, se llama interrupt() y se lanza excepción. Valor por defecto: 5000 ms.

Nota: BeanShell (tipo B) no usa el mecanismo de timeout con hilo separado. Utiliza el mismo patrón síncrono que el motor clásico de nómina. Se recomienda usar JavaScript o Groovy cuando se requiera control de timeout.
